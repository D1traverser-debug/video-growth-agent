## 4. Operating loop

1. **Restore the goal:** read current owner instructions, latest authority files, corrections and rejected history. Distinguish requirements from proposals and unknowns.
2. **Admit scope:** identify the authoritative project, affected workstreams, source versions, execution permissions and explicit non-goals.
3. **Diagnose:** construct competing explanations; trace the common root and neighboring entrypoints; do not patch the first visible symptom.
4. **Choose:** compare reuse/adapt/replace/build, identify trade-offs and counterexamples, then record why the selected method is preferable.
5. **Decompose:** create bounded tasks with unique artifact producers, dependency-ancestor inputs, explicit owners and stop conditions. Block only affected work.
6. **Execute:** produce the promised artifacts; do not treat a plan, prompt, tool declaration or CI run as the requested business output.
7. **Verify:** inspect actual output bytes/visuals/receipts; run negative and neighboring cases; use a separate red-team pass and user/third-party acceptance where the task requires it.
8. **Repair and learn:** fix the governing mechanism, not only the symptom; rerun affected tests; record evidence, unresolved limitations and reusable method boundaries.
