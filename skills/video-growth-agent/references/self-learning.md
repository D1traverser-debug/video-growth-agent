# Self-Learning Protocol

Use when a quality gap, tool limitation or superior external example appears.

1. DIAGNOSE the exact bottleneck: idea, research, script, art, motion, asset quality, sound, editing, render engineering, QA or commercial fit.
2. SEARCH for at least two plausible approaches using official docs, GitHub Skills/source, credible creator breakdowns, Reddit/X/YouTube discussions and current tools when relevant.
3. COMPARE quality ceiling, cash cost, token/credit cost, licensing, repeatability, observability and lock-in.
4. INSPECT SOURCE rather than trusting promotional claims.
5. PROTOTYPE only the high-risk part first.
6. QA the real output.
7. ACCEPT or REJECT with an explicit reason.
8. PERSIST verified lessons in code/config/reference docs; rejected approaches remain recorded so they are not rediscovered as if new.

Do not run background surveillance. Refresh knowledge during active work. Tool choice is replaceable; the quality contract is not.
