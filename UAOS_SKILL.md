## Domain-internal orchestration

One selected Video Agent may own multiple workstreams and subtasks. Do not create a new persistent Agent merely because two tasks differ.

The Video domain supports these explicit coordination patterns:
- serial dependency;
- independent parallel execution;
- fan-out/fan-in synthesis;
- consultative advice;
- competitive candidates;
- structured critique and revision;
- owner adjudication;
- panel/quorum review.

`projects/<program>/SUBTASK_GRAPH.json` or another exact domain-owned graph defines business dependencies. A task waits only for declared dependencies, required runtime artifacts and hard capability gates. Unrelated unfinished work must not become a global barrier.

Consultation is advisory. Competition means independently inspectable candidate artifacts evaluated against declared criteria. Negotiation is bounded artifact exchange such as `proposal -> critique -> revision -> adjudication`, not open-ended peer chat. Any selection/merge/rejection that governs downstream work needs an explicit authorized owner/adjudicator and durable decision evidence.

Same-context candidate diversity is exploration evidence, not independent semantic verification.

## Current-session capability handshake

Before every quality-critical generation, isolated review, media-QA or irreversible external action, handshake the exact current-session capability required by that action. Repository declarations are ceilings, not proof that a provider/tool is executable in this session.

Assurance must remain calibrated:
- `DECLARED_ONLY` — configured/known, not proven executable;
- `HARNESS_WIRED` — deterministic guard or adapter wiring exists;
- `SESSION_EXECUTABLE` — exact capability can execute now;
- `CHAT_BRIDGED` — current chat can perform a bounded specialist action without independent-provider assurance;
- `ATTESTED_ISOLATED` — distinct isolated execution is bound to provider/run/context/trace and artifact evidence.

Do not upgrade one level to another by wording alone.

## Episode production and QA

The Program/workstream graph does not replace the canonical episode production state machine. Program decisions/assets enter episode production only after explicit promotion and artifact binding.

Quality-critical generation is fail-closed. Prompts, role labels and configured adapters are not execution proof. Image/video review claims require actual modality access and evidence bound to the produced artifact identity.

Asset continuity is explicit: character, wardrobe, scene, prop, style, light, action and shot-state changes bind to versioned project assets/work orders rather than prompt memory.

Exploration/candidate outputs do not overwrite accepted/current assets until promoted. Rejected or process-invalid media never silently returns as accepted progress.

Producer completion is not approval. Where isolation is required, same-chat role switching is not independent review.

## Cost and providers

Use included/free current-session capabilities first when they satisfy the quality, permission and evidence floor. Paid or unknown-cost providers require explicit authorization. Missing hard capability blocks only the affected work unit; never fabricate generation or review.

## Cognition, learning and evolution

Every detected problem inherits the current UAOS problem-response floor: micro diagnosis, macro goal/topology alignment, governing-assumption challenge and relevant external method/architecture research. Problem size changes depth, not activation.

A successful/failing shot, project result or user correction creates evidence and may create a learning candidate. Video owns promotion of Video-specific media/growth/IP/commercial/production rules. Common or cross-domain mechanisms are proposed/upcalled to UAOS. One example never silently becomes a universal rule.

Durable domain change requires appropriate scope/generalization analysis, replay/regression/eval evidence and post-promotion observation. Avoid stacking local exceptions where a common failure class is identifiable.

## Completion

Completion requires current child business-state evidence plus the applicable artifact/review/runtime verification. Final claims must identify what actually executed, what was only configured, what decision owner approved, and what remains blocked.
